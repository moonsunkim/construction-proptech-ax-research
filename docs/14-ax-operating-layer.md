# AX Operating Layer

> 건설·프롭테크 AX의 최종 승자는 단일 기능 앱이 아니라, 도면·문서·사진·공정·비용·O&M·금융 데이터를 연결하는 운영 레이어가 될 가능성이 높다.

## 핵심 결론

초기에는 point solution으로 팔아야 한다. 하지만 장기 가치는 point solution 자체가 아니라, 그 제품이 고객의 핵심 업무 데이터에 반복적으로 접근하면서 생기는 운영 레이어에 있다.

## 진화 경로

```text
1. 좁은 업무 자동화
   예: 안전 리포트, RFI 검색, 도면 takeoff

2. 업무 데이터 축적
   예: 위험 행동, 계약 조항, 물량·견적, 현장 사진

3. adjacent workflow 확장
   예: 안전 → 일보 → 보험, RFI → 변경계약 → 클레임

4. 통합 대시보드
   예: 현장·원가·공기·리스크를 경영진 언어로 재구성

5. 예측/추천/에이전트화
   예: 지연 가능성, 원가 초과, 안전 위험, PF 리스크 조기 알림

6. 산업 운영 레이어
   설계·시공·운영·금융 의사결정의 데이터 기반 OS
```

## 해자가 되는 데이터

| 데이터 | 왜 중요한가 | 연결되는 제품 |
| --- | --- | --- |
| 도면/CAD/BIM | 공간·물량·공정의 기준 데이터 | takeoff, BIM 검토, 공정 비교 |
| 견적/내역/자재 | 원가와 수익성의 기준 | 견적 DB, 구매, 가격 예측 |
| 공정표/일보 | 시간과 지연 리스크의 기준 | 공정 리스크, 자동 보고 |
| 현장 사진/영상 | 실제 시공 상태의 truth layer | 진척도, 품질, 안전, 분쟁 증빙 |
| RFI/변경계약/클레임 | 책임과 비용 변동의 기록 | 문서 RAG, 클레임 분석 |
| 안전 near-miss | 사고 이전의 위험 신호 | 안전 모니터링, 보험/리스크 |
| O&M/에너지 로그 | 운영 수익성의 기준 | AI HVAC, 예지보전, ESG |
| 임대/공실/거래/PF | 자산 가치와 금융 리스크 | AVM, 사업성, 투자 심사 |

## 왜 point solution만으로 끝나면 안 되는가

point solution은 매출을 시작하게 해주지만, 교체 가능성도 높다. 반대로 업무 데이터와 의사결정 흐름을 장악하면 고객은 제품을 단순 도구가 아니라 운영 인프라로 보게 된다.

## 제품 로드맵 원칙

1. 첫 제품은 ROI가 선명해야 한다.
2. 데이터 모델은 처음부터 확장 가능하게 설계해야 한다.
3. 고객이 쓰던 파일과 시스템을 버리게 만들지 말고 연결해야 한다.
4. human-in-the-loop를 전제로 해야 한다.
5. 안전, 법무, 가치평가 영역에서는 “대체”가 아니라 “증강·증빙·추천”으로 포지셔닝해야 한다.

## 투자 관점 시사점

건설·프롭테크 AX의 큰 기회는 단일 업무 자동화보다, 그 자동화가 쌓아 올리는 데이터 네트워크에 있다. 투자자는 첫 wedge의 크기뿐 아니라, 그 wedge가 어떤 데이터와 adjacent workflow로 이어지는지를 봐야 한다.
